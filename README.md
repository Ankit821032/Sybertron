# Sybertron — database-backed CMS upgrade

The existing React 19 / TypeScript design is retained. The backend uses TypeScript, Express 5 and SQLite through Node's built-in `node:sqlite` driver. No separate database server is needed. Run the full application through the Node server; a static-only hosting account cannot run this backend.

## Quick start

Install **Node.js 24.18 or newer**, extract this project, and open a terminal in the project folder.

```powershell
npm ci
Copy-Item .env.example .env
```

Edit `.env`: set `ADMIN_EMAIL` and a unique `ADMIN_PASSWORD` of at least 12 characters. For local use keep `SITE_URL=http://localhost:4000`.

```powershell
npm run admin:create
npm run build
npm start
```

Open `http://localhost:4000` for the website and `http://localhost:4000/admin` for the editor. Log in with the credentials you configured. There is no default password or preinstalled administrator in this package. After creating the account, remove `ADMIN_PASSWORD` from `.env`; it is needed only for account creation/reset. Running `admin:create` again replaces that administrator's password and revokes their sessions.

Built frontend and server bundles are included, but rebuild after source changes. Keep development dependencies installed: the TypeScript runtime and build toolchain are used by these commands.

## Real photography

The website includes 19 real, locally stored Pexels photographs optimized to WebP (about 2 MB combined). They replace the abstract service/blog covers, drawn portfolio previews, sample product dashboards and remote team-photo URLs. Subjects are matched to technology services and relevant industries. Portfolio/product/team images are identified as representative photography, rather than claimed as actual project screenshots or employees.

The bundled photos appear in the Media tab alongside uploads. Change image URLs and alt text through the normal content editor. Downloaded-image source links and photographer credits are listed in `IMAGE-CREDITS.md`; machine-readable metadata is in `src/data/photoCredits.json`.

## Editing

1. Select a page, including individual product, service, article and legal pages.
2. Search for text, filter by component or content type, or click an item in the website preview.
3. Change text or headings, button labels, links, image URLs, image alt text, accessible labels and supported media attributes. Save to update the database immediately.
4. Format a text block with bold, italic, underline, strikethrough, text color and highlighting. Formatting applies to the selected text block. Headings animated as separate phrases have separate editable phrase entries.
5. Upload PNG, JPEG, WebP or GIF files up to 5 MB from the Media tab or an image field. Select a media item to use its URL. Built-in SVG illustrations can be replaced by uploaded images using the illustration fields. Existing vector logos remain usable; new SVG uploads are not accepted.
6. Choose **Shared content library** for reusable strings, including content initially hidden in tabs, carousels and closed sections. Library edits apply wherever that exact original string is rendered. Page-specific edits take priority over library edits. Header, footer, chat and cookie component fields are shared across pages.
7. Enable **Interact with preview** to operate tabs, accordions and carousels. Newly displayed fields are registered automatically while logged into the admin. Disable it again to select text by clicking.
8. Edit animated count targets through `Animated statistic values`. Equal targets used by the shared count-up helper share one setting on that page.
9. Use **Previous versions** to restore a saved field version, or **Restore original** to return to the code's original content. Concurrent edits to the same field are rejected until you reload it.

The editor manages content within the existing page/component templates. Adding routes, changing layouts, adding/removing product records, editing application behavior or configuring business logic still requires a source change. Formatting is per text block, rather than arbitrary HTML or individual character selections. Live clock values and visitor-entered form values are generated by the application.

The source data is the initial content seed/fallback; editable overrides are stored in SQLite. Rebuild after source edits. Field IDs use source component, element position and original content; moving/replacing source markup can produce new IDs. Export/back up content before structural code changes and map affected overrides when needed.

## SEO

Each real page path has independent title, meta description, keywords, canonical URL, social image and noindex settings. The server emits metadata and rendered page content in the initial response, plus Open Graph, Twitter cards and WebPage JSON-LD. Sitemap and robots responses are generated by the server. Noindex pages are excluded from the sitemap. Unknown routes return HTTP 404. The admin carries noindex headers.

Set `SITE_URL` to the actual public origin before production use, for example `https://www.yourdomain.com`. It controls automatic canonical URLs, sitemap URLs, absolute social image URLs, cookie security and same-origin checks. Configure it without a trailing path. Blank SEO fields use automatic defaults; enter distinct descriptions and titles for your business. Search rankings and indexing depend on search engines and content quality.

## Database and files

- `data/cms.sqlite`: production database, created automatically on first start.
- `data/uploads/`: uploaded images; use persistent storage for this directory.
- `database/schema.sql`: reference schema; the server creates these tables automatically.
- `legacy/original-content.json`: export of the supplied old database's pages and six section records, preserved for reference. That old scaffold was disconnected from most frontend content. Its custom `blog/New section` record is retained in this export rather than silently inserted into the existing blog layout.

Tables: `cms_pages` (SEO per route), `cms_fields` (content/format overrides and revision numbers), `cms_history` (previous values and editor), `cms_admins` (salted password hashes), `cms_sessions` (hashed tokens, CSRF and expiry), `cms_media` (uploaded-file metadata).

Back up the database and uploads together. Stop the server before copying the SQLite file, or use a SQLite online-backup tool to include committed WAL data. To restore, stop the server and restore the database and uploads to the configured paths. Admin **Export content** downloads content/SEO/history-independent records as JSON; it excludes accounts/sessions and does not include image binaries or provide an automatic full-restore function.

## Production

Use a Node-capable server/container behind HTTPS, with a persistent writable directory for the database and uploads. Set `PORT`, `SITE_URL`, `DATABASE_PATH` and `UPLOAD_DIR` as appropriate. Route **all website paths**, `/admin`, `/api`, `/uploads`, `/robots.txt` and `/sitemap.xml` to this Express app. Do not serve only the `dist` folder: that bypasses the CMS and server-rendered SEO.

Only administrators can write content or upload media. Sessions last eight hours, use HttpOnly/SameSite cookies, and use Secure cookies when `SITE_URL` is HTTPS. Mutations require a CSRF token; login attempts are limited. Passwords use salted scrypt hashes. Content renders as escaped React text with allowlisted formatting. Link/media URL schemes and image signatures are validated. Use one application instance per SQLite volume. For multi-server write scaling, migrate the database layer to a shared database service.

A Dockerfile is included. Build with `docker build -t sybertron-cms .`, mount persistent storage at `/app/data`, supply the production environment, and provision the administrator with `npm run admin:create` inside that environment before logging in. No hosting deployment has been performed.

## Development and checks

`npm run dev` rebuilds once and watches backend files. Rebuild and restart after React source changes. `npm run dev:client` runs the original Vite frontend workflow for design work; use `npm start` to verify actual database content and SEO. `npm run preview` runs the full application server.

```powershell
npm run typecheck
npm run build
npm test
```

The integration test creates an isolated temporary database and tests all known routes, authentication, CSRF, persistence, conflict handling, escaping, shared content, content-library edits, formatting, SEO, sitemap, 404s and media validation. It does not use your administrator account or production database.
